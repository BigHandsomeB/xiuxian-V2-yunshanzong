# Asset Pipeline / Prompt Builder / Asset Manager Contract
Status: ACTIVE — Phase11.5. Experience authority remains [Visual North Star](visual-north-star.md).

## Scope and ownership
Asset Manager is an independent developer tool in [tools/asset_manager](../../tools/asset_manager/INDEX.md), not a Gameplay API, Scene Composer or game runtime service. No imports of Gameplay/Foundation, no Game Save writes, no Alchemy mappings. Simulation → View Projection → future Scene Composer → stable asset_id → Manifest → Runtime file. Never reverse this direction. Game runtime must function with only manifest.json and runtime/; no manager, catalog DB, Source, Master or prompt history required.

Read North Star → this contract → relevant [Assets](assets.md), [Animation](animation.md), [Pixel Runtime](pixel-runtime.md) / [UI](ui.md) → necessary Skill. Prompt compilation takes relevant rules in this priority: North Star, pipeline, template, asset/pixel-art, animation, pixel runtime, constrained user choices. It does not concatenate every document. Changes to project art rules require reviewing the prompt compiler and templates; saved history preserves the actual text and rule-source fingerprints used at creation.

## Four storage roles
| Role | Meaning | Game access |
| --- | --- | --- |
| SOURCE | Original verified upload, possibly a sheet, retained without visual approval | NEVER |
| MASTER | Explicitly imported, manually approved and selected visual baseline | Not automatically Runtime |
| COMPONENT | Explicitly confirmed crop/frame/state/icon from a Source | NEVER |
| RUNTIME | Approved-version build at explicit final display dimensions | Manifest references only |

SOURCE NEVER DIRECTLY ENTERS GAME. MASTER DOES NOT AUTOMATICALLY MEAN RUNTIME. GAME ONLY LOADS RUNTIME ASSETS. Original inputs remain intact; recropping produces new versions, not silent replacement. Grid/Manual preview and confirmation are distinct steps.

## Data concepts and authoritative metadata
- **Asset Template**: versioned template ID, category, supported structure with exact allowed frame ranges, default action subset, row/frame layout policy, background and Master requirements, prompt/review/runtime rules. [Template data](../../assets/templates/templates.json) uses schema_version 2: explicit template_version, references to pixel_size_profiles, and optional family definitions. Stable IDs need not change when a template version advances; changes to resolved production rules require incrementing template_version, and changed reusable profiles increment their own version; the tool does not edit templates through Prompt edits. Duplicate IDs, unsupported schema, empty structure, illegal ranges/default actions are rejected. Defaults are choices; AI does not invent actions or counts.
- **Asset Set**: stable set ID, template, required states/actions, ID prefix, labels and navigation-only Used By. Independent collections use ordered member IDs; scene/state sets use state slots plus a Master reference. A single character Asset owns all of its action/frame Components. Historical action-per-slot sets remain readable; a Source Sheet does not create an Asset per frame. Asset/Set family is explicit; selected Source must match it. Legacy unbound assets freeze their family on first import. Required states are explicitly selected from the template. Completeness excludes Master from the state denominator.
- **Asset**: stable asset_id, mutable name_zh/tags, category/template/set/state references, ordered immutable-import versions and explicit current_approved_version. Filename is not identity. Renaming never renames IDs. Creating a duplicate fails. No presentation data enters Gameplay Definitions.
- **Source Asset**: generated internal source_id/file path, original filename, verified dimensions/checksum, template/set/prompt references and timestamp. Upload is not approval. Original filenames never determine storage paths.
- **Runtime Asset**: immutable build files, explicit dimensions, frame/action mapping, format, checksum, nearest sampling and build time, attached to an approved logical asset version.

Live metadata owner is a dedicated asset-only SQLite catalog at assets/registry/catalog.sqlite3 (schema 1), with transactional JSON records for assets, sets, sources and prompt instances. It is not Gameplay persistence or a second Gameplay authority. [asset-registry.json](../../assets/registry/asset-registry.json) is tracked **bootstrap set data**, not a competing live catalog; /api/registry exports the complete live Registry snapshot. SQLite stores metadata, never image blobs. All queries return detached records and have no Simulation effect.

## Set and version lifecycle
Art Status is per version: draft → needs_review → approved; any active status may become deprecated. Deprecated is terminal for that version; revisions require a new version. Missing_source is a **slot completeness diagnostic**, not an approved Art Status. Import creates draft. Advanced review keeps separate checklist, selection, build and publish actions. Ordinary Quick Confirmation combines these steps in one explicit human action after all batch previews load, retaining their complete records; see the workflow below. It does not implicitly approve uploads or overwrite files of an older version.

Old versions and builds are retained by default. Deprecate Asset explicitly deprecates all existing versions and unpublishes the logical ID, without deleting files; replacement requires a new draft version. Current selection and published version may differ until explicit Publish. Deprecating a published version removes its Manifest entry even if a different approved version has since been selected. Controlled permanent purge is available only through the explicit impact/confirmation lifecycle described below. Source deletion is limited to unreferenced sources; Runtime deletion requires a deprecated/non-approved, unpublished build. Referenced inputs and approved/published Runtime cannot be deleted. No dangling Manifest references are intentionally published.

## Prompt contract and traceability
Structured choices use the shared specification resolver: template/family, supported subject size, selected actions/counts, object/use, quality, approved Master, locked features and notes. Pixel Size Profile and Visual Quality are independent. The primary UI displays logic size, Source Cell, gaps, safe padding, anchor and Runtime profile read-only; supported size choices come from data. Advanced overrides are explicit instance-only records and cannot reduce cut safety. There is no independent blank Runtime-size input in the normal flow.

Frozen Prompt Snapshot records prompt_id, template_id/version, pixel profile ID/version, subject_logic_size, source_cell_size, spacing, inner_safe_padding, anchor, runtime_profile, action_spec, frame_counts, row_order, row/column counts, output_mode, transparent, grid_spec, overrides, selected template snapshot, source-rule fingerprints and complete text. Generation saves this immutable history before copy/upload; edits append another history record. Regeneration uses current rules but never changes old snapshots. English output sections cover the current asset, art direction, logical pixels/runtime, cut safety, actions/states, low-frame principles, type-specific rules, references, changes/locks, text/quality/reuse, layout, prohibitions and final output. User-entered names/notes retain their original language. No image API.

Source uploads linked to Prompt retain that exact frozen specification. Without a Prompt, the user explicitly chooses template/family and the tool creates an Import Specification Snapshot. Native upload size is measured separately, not substituted for logical size. Import and Review read source/version snapshots rather than today's template. Runtime can explicitly use the current item export profile under the recorded policy below, while generation and crop snapshots remain immutable. Historical Prompt snapshots remain honest legacy records with their original frame ranges; unbound historical uploads require explicit binding, not silent guesses. Template upgrades cannot relabel old Source rules. [Operator workflow](../../tools/asset_manager/README.md) explains this path.

## Import, slice and mapping
Allowed inputs: single non-animated PNG, JPEG, WebP; verified contents must match extension. Maximum 12 MiB upload, dimension ≤8192 per side and total ≤16 Mi pixels. Reject corrupt/animated images, traversal, absolute paths, hidden/unsafe names and scripts. Files receive unpredictable names, are not overwritten by matching original filenames and stay in the explicitly configured V2 asset workspace. Original filenames are display metadata only: ordinary Unicode letters, punctuation, symbols and spacing (including Chinese brackets and export timestamps) are accepted. Reject path separators, drive-prefixed paths, hidden names, control/format characters, line separators and invalid code points; never use the display name as an output path.

Grid: rows, columns, frame_width/height, horizontal/vertical gap and four margins; maximum 256 regions, summed slice area ≤16 Mi pixels. Cell rectangles must fit inside the source. Default geometry and action rows come from the Source frozen specification; custom mapping allows corrected grids such as a 2×3 Scene Sheet. Unused cells are not automatically imported.

Manual: touch/mouse drag or explicit integer x/y/width/height; corrected geometry is recorded while frozen action meanings/counts remain enforced; positive non-empty in-bounds rectangles, each labeled action and 1-based frame. Mapping must exactly cover every selected action/frame, without duplicates. No AI recognition/OCR. Source checksum is revalidated on execution; bounds and mapping are revalidated during import. Confirming a target state imports its mapped subset as a new version. Sprite assets can contain several actions or one action per Set slot. Scene Sheet and independent full-image imports use the same pipeline; high-detail interiors favor separate images. A Master may use a full source or confirmed crop. Individual frame replacement creates a new draft version retaining unchanged components, with parent-version/per-component Source provenance and exact matching viewport dimensions; it never mutates an approved frame in place.

## Review and approval
General checklist: style, dimensions, background, composition, mapping, frame isolation, target Runtime clarity. Interior state checklist additionally checks camera, architecture, furniture, perspective, base lighting, character scale, workstation, pixel density, local changes and selected Master consistency. A state records the exact selected Master version at approval. Approval is human (advanced checklist or explicit Quick Confirmation of all retained previews), not automated visual verification; file checks alone do not prove art quality. Do not approve inaccessible/missing references or assume images from chat are present.

## Runtime build and publication
Runtime dimensions/policy normally come from the imported version’s frozen profile. Game item templates explicitly opt into `current_item_profile` in the sole Template authority; the normal tool flow previews that current export, independently of historical generation dimensions. [Item export Decision](../decisions/ASSET_ITEM_ICON_PROFILE_V2.md) records the user-authorized change. The Catalog builder defaults to the declared item export policy (also for direct API calls), and keeps an explicit `frozen` export option for historical reproduction. Export changes never rewrite Prompt/Source/Component/mapping/approval or create new art versions. For an old grid component, the original subject-to-cell crop fraction is retained; actual subject crops still fit their existing region. Only the output target changes. Each successful build appends immutable `runtime_build_history` with build_version, export origin (template/profile versions), checksum, dimensions and files; previous output files remain intact. Quick previews freeze the export origin and reject a changed origin before building, so the confirmation cannot publish a size the user did not preview. Master assets never opt into item Runtime export. Preserve transparent sprite cells (pad smaller corrected crops at the fixed anchor), crop centered icon subject regions with exact pixel boundaries, or resize complete scenes with preserved aspect ratio; Pillow NEAREST, PNG or lossless WebP. Source native size, Master crop size and Runtime target are displayed separately in asset provenance. Legacy versions retain their historical explicit-size build flow and are identified as legacy. Integer scale (or exact reciprocal downscale) is preferred; non-integer resize requires explicit acknowledgement and subsequent phone clarity review. Dimensions ≤4096 per side, total frame area ≤16 Mi pixels. Source/Component integrity is checked before processing. Builder produces normalized immutable runtime/<asset_id>/vN/<generated-name> files, never browser CSS-downscaled Masters. No Atlas packing, AI background removal, GPU or image daemon.

PNG is the default for crisp alpha sprites/icons/effects; lossless WebP is offered for complete scenes and where measured size/alpha support is useful. No forced universal format or lossy pixel sampling. Final game display sizes remain task-specific; this phase does not lock invented BATTLE_PLAYER or BUILDING dimensions.

[manifest.json](../../assets/manifest.json), schema 1, contains only explicitly selected approved versions with completed, present, checksum-valid Runtime files. Per asset: art version, Runtime build version/export origin, format, sampling and files with action/frame, width/height/checksum. Source/Master/Component paths are excluded. A single atomic replace publishes the manifest after all entries are checked. Existing published files are retained across builds and version switches, so readers see an intact old or new manifest.

Metadata commands use BEGIN IMMEDIATE transactions. Failed imports/builds roll back metadata and do not publish partial output; an unreferenced staged file may remain after failure and is not game-loadable. Deprecation unpublishes first, then commits metadata (fail-closed: an interrupted deprecation may temporarily hide an otherwise approved asset, never advertise a deprecated replacement); Publish reconstructs from valid catalog facts. Filesystem and SQLite are not claimed to form a distributed ACID transaction. Immutable outputs and atomic manifest are the game-facing safety boundary.

## Static collections and Chinese creation

Ordinary creation asks for a Chinese name, Template, single/set scope, ordered names and independent/sheet output; machine IDs/family are collapsed advanced fields. Runtime role is read-only. Deterministic hash suggestions avoid requiring translation; collision handling is transactional, explicit overrides validate ASCII, and changing display names never changes IDs.

Four counts are independent: Asset Set Count, Asset Count, Action Count and Frame Count. A static_collection Set stores ordered asset_ids; Asset Count is derived from membership. Every static member has frame_count=1. Dynamic actions/frames retain their existing contracts. Static Prompt UI hides action/frame controls and uses generation scope/list/output. Shared set specification is in [sets.py](../../tools/asset_manager/sets.py); no parallel frontend authority.

The saved static Prompt specification extends the existing snapshot with generation_scope/mode, asset_set_id, asset_list, asset_ids/asset_order, derived asset_count, grid_rows/columns and cell_mapping. Each cell contains asset_id, name, row/column and one static frame. Unused cells remain unassigned. The catalog, not user-submitted counts or a copied UI list, supplies existing Set membership. Source Sheet text explicitly requests different independent assets, not animation frames. Independent mode selects a single member's Prompt for upload; sheet mode uploads one Source with all frozen cell bindings.

Static Set details expose add/delete/reorder/rename. Stable IDs survive rename/order changes. Removal detaches present Set membership and retains the independent Asset, versions and immutable Source/Prompt history; deprecation additionally withdraws the Asset from Manifest. New Prompts reflect the new list, while previous Prompt/Source snapshots retain their mappings. Explicit approved same-Template icons may serve as shared visual references; this does not weaken Interior Master validation.

Sheet/manual import validates coverage and unique asset identities, then creates each member's own single-frame version in one existing catalog transaction. A failure rolls back all metadata and does not publish partial output. Approved versions continue to build independently and publish through the existing Manifest gate. Import does not infer identity from pixels. [Decision](../decisions/STATIC_ASSET_COLLECTION_V1.md) records rationale. No Gameplay/Resource identity is created by naming a visual asset.


## Actual source geometry localization
Mapped Source Sheets of every supported semantics default to Auto Locate, with Frozen Grid and Manual Slice retained. [geometry.py](../../tools/asset_manager/geometry.py) detects only foreground locations on a bounded thumbnail: alpha mask first, uniform edge-color estimate as fallback, connected components, noise filtering and conservative nearby fragment merging. Expected active Cell count and row layout come from the Source frozen snapshot. Cell count is not Asset count: one character can have many frame Cells. Complete scene panels without separable foreground may fail localization; Frozen Grid/Manual Slice remain necessary fallbacks. Uncertain counts are never forced into guessed identities; FAILED enters manual mode, NEEDS_REVIEW requires human boundary/layout checks. No AI Vision/OCR/semantic naming or additional dependencies.

Geometry sorting follows frozen row/column order. Names and stable asset_ids come only from frozen cell_mapping; detected visual colors/shapes cannot identify resources. Padded source bounds are mapped back to native coordinates and constrained by source edges and neighbor midpoints. The phone canvas shows frozen Chinese labels and supports selected-box drag, corner resize and numeric boundary edits. Any edit invalidates the checked plan; import requires validation and explicit confirmation.

Confirmed imports append source_region_mappings (mode, source checksum, expected layout, actual regions, detection provenance, confirmation time) in the same metadata transaction as all mapped draft versions (one character version can contain many frames). Prompt/Source frozen specifications and original rasters remain unchanged. Failed import leaves neither partial versions nor confirmed region history. Detection itself is a pure preview.

For static auto/manual subject crops, Runtime fits the whole actual region into a transparent canvas with the frozen target aspect and an exact reciprocal nearest downscale. It does not repeat the theoretical centered Source Cell crop, stretch a non-square subject or change the frozen Pixel Profile. Opaque-background fallback crops retain that background; detection is not background removal. Human Runtime clarity review, approval, selection and explicit Manifest publication remain mandatory. Frozen Grid retains theoretical-cell export; actual sprite regions restore the profile canvas and feet baseline, and non-proportional actual scene panels fit into the frozen viewport without distortion. Every path uses nearest sampling. Source Container never selects Runtime packaging.


## One-action human confirmation
[workflow.py](../../tools/asset_manager/workflow.py) coordinates the existing catalog lifecycle through two operations: prepare a server-owned preview, then explicitly confirm its preview_id. Source Sheet geometry remains frozen semantically; the prepared snapshot captures actual coordinates, asset/version fingerprints, per-item diagnostics, complete crop previews and exact frozen Runtime previews. Preparing/uploading never approves or publishes. The ordinary button is disabled until required preview images have loaded. All valid items are retained by default; no repeated selection/checklist clicks. Each item may be excluded. Advanced review/build/publication controls remain collapsed and available.

Clicking “确认并完成导入” is explicit human consent to review and approve the retained displayed items, build their Runtime and update Manifest. The UI states this scope and shows any non-integer nearest-resize acknowledgement alongside final-size previews. The authenticated adapter assigns the operator identity; a client cannot forge approved_by. Review/approval remain draft→needs_review→approved; approved_at/by, transition history, approval source, prompt/source references, actual slice mapping, Runtime validation and completion results are recorded. No new Gameplay authority or save state exists.

The confirmation checks source integrity, preview/file integrity, mapping and asset fingerprints again. Asset changes invalidate the prepared preview. Replays of the same confirmed preview and exclusions return its result without duplicate imports; changed exclusions conflict and require a new preview. Prepared previews expire after two hours, but completed audit/replay history remains. Explicit Source cleanup may retire those historical previews or cancel still-pending previews; retired records retain their frozen specifications/results but cannot reconfirm/re-publish or serve removed raster evidence (see lifecycle Decision). Registry exports include review_previews; raster evidence stays in the existing private component storage.

Each item uses a savepoint around approval/build/validation/selection. Empty/out-of-bounds/overlapping/damaged crops or failed builds remain needs_review with diagnostics; healthy siblings complete. Excluded new items remain unapproved. Invalid imports may retain a needs_review diagnostic version with no Components; these cannot be approved. Previously approved/published versions stay available when a replacement is excluded or fails. Excluding a new version does not deprecate an older publication.

After the metadata transaction commits, publication uses the existing approved-selected-valid-Runtime Manifest gate and atomic file replacement. A publication failure is visible and retryable without rebuilding/re-importing completed items. This does not claim distributed filesystem/SQLite ACID. Staged failures remain unreferenced. Source/Components/previews never enter Manifest.

Static single images and independent static batches use the same confirmation operation. Dynamic Sprite previews show all selected actions/frames; marking one action needs correction keeps that whole Sprite pending, never publishes partial-frame animation. Already imported Asset/Set versions may be prepared for the same one-action review. Scene batches approve only the explicit previewed versions, select a previewed Master first if present, and enforce the existing approved Master reference for states. Unviewed/missing Master or state images are never implicitly approved. Rendering/Alchemy mappings remain absent.

Formal version/shared-file/other-Source/Manifest references remain protected. Whole-set deletion has a visible batch entry; container-only deletion preserves members. ## Unified Source Container and Sheet semantics — current authority
[Template data](../../assets/templates/templates.json) and [sheets.py](../../tools/asset_manager/sheets.py) own this model; [Decision](../decisions/UNIFIED_SOURCE_CONTAINER_V1.md) records compatibility and scope. Generation Scope is only single_asset / asset_set. Source Container is only single_image / sheet / image_set. These are independent: a single character can use a sheet with many action frames; a collection can use one sheet or independent images. Static/Dynamic does not grant or prohibit Sheet access.

Every Template/family declares default/allowed Source Containers and default/allowed Sheet Semantics. When Container is sheet, Semantics is mandatory and restricted to independent_assets, action_frames, state_sequence, scene_states, environment_variants, effect_frames, ui_states, tiles or nine_slice. Ordinary UI shows Chinese generation methods and automatically derives their meaning from Template/family; internal names remain stable ASCII. source_container is not Runtime packaging, art quality, Gameplay meaning or Frame Count.

Common geometry reads layout_spec and translates it at the old grid-validator interface. Cell keys include asset_id + action/state + frame, so repeated character identity across frames is valid. Only active cells are mapped; unused cells stay unassigned.

Character/monster/Boss/beast sheets are action_frames; all a single object's action Cells import into one Asset version. Effect sheets use effect_frames. Independent icon Cells remain separate one-frame Assets. Interior sheets contain six COMPLETE Scene State panels and exclude the Master; an approved selected Master is still required. image_set and sheet resolve the same Set member IDs. Twelve-time environment family freezes twelve non-animation variants; herb growth freezes non-animation states. UI states and nine-slice parts are independent presentation components; terrain-family item lists use tiles. These are visual definitions only, no Alchemy/UI gameplay/scene rendering or new Runtime system.

The unified Sheet importer reads frozen cells/layout, uses the existing grid/manual/Auto Locate geometry, groups Components by final Asset identity and creates versions in one catalog transaction. Quick Confirmation uses the same grouping and existing approval/build/Manifest lifecycle. Auto Locate only assigns detected rectangles to frozen Cells in row-major order; it never identifies characters/resources/states from pixels. Frames with the same Asset ID remain distinct through action/frame keys.

Historical Prompt/Source JSON is NEVER rewritten. canonical_spec projects legacy single/set scope and static_asset_sheet, sprite_sheet, scene_state_sheet (and supported aliases) from that record's own frozen Template/counts/geometry; it never consults a newer Template to reinterpret Source. HTTP exposes a detached import_spec view alongside untouched frozen_spec. Image-set uploads require an explicitly selected single Asset/state or action group; uploading an ambiguous whole multi-image Prompt is rejected. collection是Catalog metadata中的轻量目录，不是制作模板或Runtime类别。collection_id可附在set或不属于set的asset；组内资产从set解析父集合。整理、移动、重命名不改变Asset ID、冻结规格、Source、Prompt、批准、Manifest或游戏引用。新建时验证父集合在同一事务存在，拆组独立素材继承父集合；非空集合不可删除。集合内可并列任意类型制作组，集合不自动生成配置/素材/游戏物品。
