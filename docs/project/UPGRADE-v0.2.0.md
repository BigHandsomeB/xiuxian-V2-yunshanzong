# 从 v0.1.0 升级至 v0.2.0

新玩家按README运行setup_local即可获得当前完整新档。以下仅适用于自己已有的v0.1.0存档，升级前停止自己的游戏服务。

1. 备份原项目的整个`.game/`目录及当前代码版本，保留数据库、save-id和自己的口令配置。备份不要提交到GitHub。
2. 更新至v0.2.0，保留`.game/`；不要运行setup_local或删除存档。依赖沿用原版本。
3. 在项目目录执行只读预检：

```sh
.venv/bin/python -B -m tools.playable.combat_effect_upgrade
```

预期旧内容版本为`sect-ecology-v1-6.3.0-r1`，且pending=False。如果存在待完成离线续算，先用原v0.1.0代码完成续算，停止服务后重新检查，不跳过校验。更早版本不在此次直接迁移范围。

4. 确认预检后执行显式升级：

```sh
.venv/bin/python -B -m tools.playable.combat_effect_upgrade --apply
```

工具先在项目`.tmp/`生成权限600的完整SQLite和JSON备份，再通过已有事务/回执设施提交内容版本。只改内容版本和revision，不发放资源、不重抽旧装备、不改进度、时间或原战斗。备份路径在命令结果中返回，请将它们另外安全保存；`.tmp/`不进入Git。

5. 按README恢复自己的服务并刷新游戏。原战斗继续使用原快照；新规则用于后续新战斗。若返回ALREADY_UPGRADED，不重复执行迁移。

升级后新生成的战斗/装备不能由旧代码完整解释。需要回退时先停止服务，恢复升级前的完整SQLite/相关路由文件与对应旧代码，不能仅覆盖旧代码。恢复会丢弃备份后取得的进度，勿覆盖仍在运行的数据库。

当前单实例共用一份存档，不支持通过此工具合并不同玩家存档。首次游玩与旧档迁移是独立流程。
